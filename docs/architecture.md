# shoe-box-tools architecture

shoe-box-tools standardizes how Ethan's repos are built. It has two halves:

1. **Shared config packages** (published to npm under `@shoe-box-tools/*`). Anything
   that can be imported instead of copied lives here, so a preference change
   reaches every repo through a version bump.
2. **`shoebox` CLI** (`@shoe-box-tools/cli`, Effect 4.0.6 `effect/cli`). It scaffolds new
   repos (`init`) and keeps existing ones current (`sync`, `doctor`, `adopt`,
   `migrate`, `check`).

See `docs/preferences.md` for the preferences themselves and where each came from.

| `@shoe-box-tools/cli`            | `shoebox` binary + `defineConfig` for `shoebox.config.ts`                                              |
| `@shoe-box-tools/utils`          | Effect helpers (CommandUtils)                                                                          |
| `@shoe-box-tools/spanoptic`      | Unrelated trace TUI (OpenTelemetry + @opentui/core, runs under Bun); private                           |

Workspace packages export TypeScript source (`exports` -> `./src/*.ts`). Published
packages switch to built output via `publishConfig.exports` (tsdown -> `dist/*.mjs`),
because Node refuses to type-strip files under `node_modules`.

### Generation model

Generators are **pure functions** `(ctx: GenContext) => Contribution`. A contribution
holds files plus facts other files need: task definitions, env vars, catalog entries,
nix packages, gitignore lines, ignore globs. `generate()` runs every generator, merges
the facts into an `Aggregate`, then runs **renderers** `(ctx, aggregate) => files` for
files that depend on the whole repo: the root `package.json` catalog,
`turbo.jsonc`/`nx.json`, `.env.schema`/`secretspec.toml`, `flake.nix` and `.gitignore`.

Content is rendered with TypeScript template literals, with no handlebars. A file
that would need more than a few conditionals gets a small typed builder instead.

Versions come only from `ctx.version(name)`. An unknown name throws, so nothing is
ever emitted as `latest`.

### File strategies (`FileStrategy`)

- `owned`: fully regenerated by every sync. If the file was edited by hand (its disk
  hash differs from the lockfile baseline), sync reports a conflict instead of
  overwriting it.
- `seed`: written once if missing (app source, README). Never touched again.
- `managed`: the file has `shoebox:begin <id>` / `shoebox:end <id>` comment markers.
  Sync rewrites only the region bodies. Use this for files the user also edits, such
  as AGENTS.md or `oxlint.config.ts` project overrides.
- `json-merge`: deep-merges the keys shoebox owns into existing JSON (package.json).

### Sync engine

The engine follows the idea used by Better-Fullstack's `bts.lock.json`, without its
transaction machinery:

- **Lockfile.** `shoebox.lock.jsonc` records the CLI version, the applied migration
  ids, and one sha256 per file of the content shoebox last wrote (CRLF hashed as
  LF). For managed and json-merge files it also records what that hash covered
  (region ids / owned key pointers), so a version that owns more or fewer keys is
  compared against what was owned at the baseline, not mistaken for a hand edit.
  Seeds get a baseline only when shoebox wrote them.
- **Plan.** `sync` renders into memory, then sorts every file into one of: `create`,
  `update` (disk matches baseline, so it is safe), `unchanged`, `conflict`
  (hand-edited since the baseline, or a managed region removed or duplicated),
  `untracked` (exists but has no baseline, the adopt case) or `skip` (seed that
  already exists, or that shoebox wrote and the user deleted).
- **Apply.** `--dry-run` prints the plan with diffs. By default sync refuses a dirty
  git tree (and fails closed when git cannot report status). `--force <glob>` takes
  the generated version for conflicts; for a managed file that is the generated
  region bodies, and text outside regions is always kept. Git is the undo button.
- **Formatting.** Generated TS/JSON is formatted with oxfmt before it is hashed, so a
  formatter run never shows up as drift.

### Task runner abstraction

`TaskDef` (in `generators/task-runner/model.ts`) uses turbo's syntax (`^dep`,
`//#root`, `with`). Package scripts stay as leaf commands. The aggregate tasks
(`lint`, `lint:check`) have no script and only fan out.

- The **turbo** renderer emits root `turbo.jsonc` plus per-package `turbo.jsonc`
  overrides.
- The **nx** renderer emits `nx.json` `targetDefaults`. Nx infers targets from
  package.json scripts, and aggregates become `nx:noop` targets with `dependsOn`.

Switching runners means changing `taskRunner` in `shoebox.config.ts` and running
`shoebox sync`.

### Secrets abstraction

`EnvVar[]` is rendered to:

- **varlock:** `.env.schema` with `@generateEffectConfig(effectVersion=4)` /
  `@generateTsTypes`.
- **secretspec:** `secretspec.toml` with `default`/`development`/`staging`/`production`
  profiles.

Either way, app code reads env only through the generated `@scope/env` package
(Effect `Config`), and the `no-raw-env-access` lint rule enforces that.

## Conventions for code in this repo

- Effect 4.0.6 everywhere: `effect/cli` (Command, Flag, Argument, Prompt),
  `effect/FileSystem`, `effect/Path`, `@effect/platform-bun` (`BunServices`,
  `BunRuntime`). Tests use `@effect/vitest` (`it.effect`, `assert`), run with
  `bun run test` (vitest), never `bun test`.
- Inferred return types; minimal comments, used only to explain a non-obvious *why*;
  no `any` and no non-null assertions.
- Every oxlint rule change carries a one-line reason comment above it.
- Zero warnings: rules are `error` or `off`.
- jsonc wherever a tool accepts it; TypeScript config wherever a tool accepts it.
