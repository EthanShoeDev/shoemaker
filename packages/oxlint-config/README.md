# @shoe-box-tools/oxlint-config

The shared `oxlint.config.ts` for Effect + bun monorepos, built on [oxlint-flat-config](https://github.com/liangmiQwQ/oxlint-flat-config). There are two ways to use it:

- `defineShoeboxConfig(options)`: one call with a few options. This is what `shoebox init` generates.
- `shoeboxPreset(options)`: the same config as an array of named flat config blocks. Use it with the composer when a repo needs to change one block.

Install it beside `oxlint`, `oxlint-tsgolint` and `@effect/tsgo` (peer dependencies), and run `effect-tsgo patch --oxlint` from `prepare` so the `effecttsgo/*` rules exist. The custom plugins (`@shoe-box-tools/oxlint-plugins`), the third-party eslint plugins, `oxlint-flat-config` and `@oxlint-flat-config/composer` are dependencies of this package. The `jsPlugins` entries are absolute paths resolved from here, so the consuming repo does not list the plugins itself.

## `defineShoeboxConfig`

```ts
// oxlint.config.ts
import { defineShoeboxConfig } from '@shoe-box-tools/oxlint-config';

export default defineShoeboxConfig({
  scope: 'myproj', // workspace scope without the @
  react: true,
  tanstackRouter: true,
  web: true,
  ignorePatterns: [
    // Generated by the extractor.
    'packages/data/src/generated/**',
  ],
  overrides: [
    {
      // Bit-field parsing of save files.
      files: ['packages/save-parser/**'],
      rules: { 'no-bitwise': 'off' },
    },
  ],
  rules: {
    // Every route module is lazy.
    'dynamic-import/no-unexplained-dynamic-import': 'off',
  },
});
```

| Option | Effect |
| --- | --- |
| `scope` (required) | Workspace scope. `env-access/no-raw-env-access` points at and allows `@<scope>/env`. |
| `react` | Adds the `react`, `react-perf` and `jsx-a11y` categories, their offs, the React Compiler offs, and ignores `**/components/ui/**` (shadcn). Without it no React rule runs. |
| `tanstackRouter` | Enables `route-active/no-render-time-match-route`, turns `typescript/only-throw-error` off (`throw redirect()`), and with `react` turns `react/only-export-components` off for `**/routes/**`. |
| `tanstackQuery` | Every `@tanstack/eslint-plugin-query` rule at `error`. |
| `playwright` | Every `eslint-plugin-playwright` rule at `error` for `playwrightFiles` (default `e2eFiles`), minus the rejected ones. |
| `testingLibrary` | Every `eslint-plugin-testing-library` rule at `error` for `testingLibraryFiles` (default `testingLibraryFiles`). |
| `web` | `env.browser` and `backdrop-filter/no-backdrop-filter`. |
| `ignorePatterns` | Appended to the shared ignores. They use oxlint's gitignore syntax, so `CLAUDE.md` matches at any depth. |
| `overrides` | Appended after the shared blocks, so they win over them. An oxlint override (`{ files, excludeFiles?, rules }`) keeps oxlint's glob meaning (`*.ts` matches at any depth). A flat config item, meaning one with a `name`, `ignores`, `basePath` or `extends`, is passed through unchanged with flat-config globs. |
| `rules` | Project rules. They sit after every shared global block and before the shared scoped blocks, where oxlint's root `rules` used to apply, so the test and tooling offs still win over them. |

## `shoeboxPreset` and the composer

`shoeboxPreset(options)` takes the preset options (everything above except `ignorePatterns`, `overrides` and `rules`) and returns plain flat config items. Pass them to `defineFlatConfig` (oxlint-flat-config's `defineConfig`) or to `composer`; both are re-exported, so no second install is needed.

```ts
// oxlint.config.ts
import { composer, shoeboxPreset } from '@shoe-box-tools/oxlint-config';

export default await composer(shoeboxPreset({ scope: 'myproj', react: true }))
  // This repo has no env package yet.
  .override('shoebox/custom', {
    rules: { 'env-access/no-raw-env-access': 'off' },
  })
  // Benchmarks are linted like source code here.
  .override('shoebox/tests', (block) => ({
    ...block,
    files: block.files?.filter((glob) => glob !== '**/perf/**'),
  }))
  // No vendored code in this repo.
  .remove('shoebox/vendored')
  .insertAfter('shoebox/node-tooling', {
    name: 'myproj/codegen',
    files: ['packages/codegen/**'],
    rules: {
      // The generator prints its plan.
      'effecttsgo/global-console': 'off',
    },
  });
```

Blocks, in order:

| Name | Kind | What |
| --- | --- | --- |
| `shoebox/ignores` | global ignores | Build output, generated code, cloned docs, agent dirs (+ `**/components/ui/**` with `react`) |
| `shoebox/options` | global | `typeAware`, `typeCheck`, `reportUnusedDisableDirectives: 'error'` |
| `shoebox/plugins` | global | The `jsPlugins` entries (+ `env.browser` with `web`) |
| `shoebox/categories` | global | `category()`: all six categories at `error` for the enabled plugins |
| `shoebox/base` | global | Formatter-owned, budget, style, TypeScript, Effect-shaped, promise, module, JSDoc and vitest offs |
| `shoebox/react` | global | `react` only |
| `shoebox/tanstack-router` | global | `tanstackRouter` only |
| `shoebox/web` | global | `web` only |
| `shoebox/effect` | global | `effectTsgoRules` and the rejected Effect rules |
| `shoebox/custom` | global | The custom plugin rules (`env-access`, `import-boundaries`, …) |
| `shoebox/anti-slop` | global | Every anti-slop rule at `error`, minus the rejected ones |
| `shoebox/tanstack-query` | global | `tanstackQuery` only |
| `shoebox/dts` | scoped | `**/*.d.ts` |
| `shoebox/tests` | scoped | `testFiles` |
| `shoebox/routes` | scoped | `routeFiles`, `react` + `tanstackRouter` only |
| `shoebox/playwright` | scoped | `playwright` only |
| `shoebox/testing-library` | scoped | `testingLibrary` only |
| `shoebox/node-tooling` | scoped | `toolingFiles`: scripts, config files, oxlint plugins |
| `shoebox/vendored` | scoped | `vendoredFiles` |

Order matters as in ESLint: a later block wins. A rule added with `.append()` therefore also wins over `shoebox/tests`. To get `defineShoeboxConfig`'s placement for project rules, use `.insertBefore('shoebox/dts', { name: 'myproj/rules', rules })`. Patterns in flat items follow flat-config rules: `*.ts` matches only in the config's directory, so write `**/*.ts`. Global ignores are anchored, so write `**/dist` (see oxlint-flat-config's `docs/differences-from-eslint.md`).

## Other exports

- `everyRuleOf(prefix, plugin)`: every rule of a jsPlugin at `error`.
- `effectTsgoRules`: every rule from every `@effect/tsgo` oxlint preset at `error`.
- `effectVitestTestBlocks`: `it.effect`, `it.live`, … with modifiers, for `vitest/no-standalone-expect`.
- `resolvedPlugin(name, specifier)`: a `{ name, specifier }` jsPlugins entry resolved to an absolute path.
- Block builders: `testOverride`, `toolingOverride`, `vendoredOverride`, `declarationOverride`, `playwrightOverride`, `testingLibraryOverride`, `routesOverride`. Each returns the named scoped block and takes the files it applies to.
- Globs: `testFiles`, `e2eFiles`, `testingLibraryFiles`, `toolingFiles`, `vendoredFiles`, `declarationFiles`, `routeFiles`, `sharedIgnorePatterns`, `reactIgnorePatterns`.
- From oxlint-flat-config: `composer`, `defineFlatConfig`, `category`, `globalIgnores` and the `FlatConfigItem` type.

## Strictness model

- All six categories (`correctness`, `perf`, `restriction`, `suspicious`, `pedantic`, `style`) are at `error` through `category()`, so a rule is on unless a later block turns it off. flat-config enables every built-in plugin, so the category's plugin list (plus `react`, `react-perf` and `jsx-a11y` with `react`) decides which built-in rules run.
- Every jsPlugin rule is at `error` through `everyRuleOf`, and every `@effect/tsgo` rule from every preset is at `error` through `effectTsgoRules`. A new upstream rule therefore lands at `error`, never at a preset's `warn`.
- Every rule we reject is turned `off` with its reason on the line above it. No rule is at `warn`: the result is zero warnings, with `reportUnusedDisableDirectives: 'error'` and `typeAware`/`typeCheck` on in `options`.
- Offs follow the spreads they override, because a later spread re-enables anything above it.
- The base is listening-astro's generic config, reconciled with elden-ring-compass's stricter choices (elden turned back on about 39 rules listening-astro had off). Project-specific offs from either repo stay out; a repo adds them in `rules`, `overrides` or a composer step with its own reason.
